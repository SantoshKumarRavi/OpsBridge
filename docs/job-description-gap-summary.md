## What is already added

- Multiple frontend and backend frameworks as isolated examples, to demonstrate breadth without combining duplicate stacks in one service.
- The main multi-tenant onboarding workflow, API gateway, compliance API, AI runtime, integration service, event processing, database adapters and observability configuration.
- AI-assisted development setup and automated tests/evaluations in the repository. These are workflow artifacts; review and verification still need to happen for each change.
- DSA practice code and a separate interview-preparation map.

1. Review a credentialed AWS plan and perform a controlled deployment of one coherent user workflow with logs, health checks, autoscaling and rollback evidence. The Terraform slice now includes the worker, realtime service and Kafka projection consumer; external brokers and full observability still need deployment/runtime verification.
2. Get a successful hosted run of the full Docker-backed workflow and Kafka projection assertion. It exercises PostgreSQL, RabbitMQ, a separate Celery worker, the AI runtime's safe default/mock provider path, Kafka outbox publication and the projection's PII-minimization rule; retain CI evidence. It does not make credentialed external LLM calls.
3. Verify cross-service OpenTelemetry traces and alert delivery, then document one incident/RCA exercise.
4. The voice-policy slice now has stored tenant consent/suppression, audit history, an Angular reviewer form, and a fail-closed Vapi gate. Remaining voice work is independent evidence verification, authoritative external DNC synchronization, jurisdiction-specific rules, provider callbacks/recording, and credentialed end-to-end verification.
5. Run a repeatable RAG quality/latency/cost comparison and publish the result artifact.
6. Keep regulated domain areas and interview/professional skills as separate study evidence; do not imply the synthetic examples provide regulatory compliance or personal mastery.

## About counts

The checklist mixes named products with concepts and personal skills, so a single exact “added versus missing” bullet count would be misleading. Flutter now has a locally built Android debug APK, but that alone does not verify iOS signing or device OIDC flows. The row-by-row status above is therefore the useful count level: broad areas and explicit remaining evidence.
