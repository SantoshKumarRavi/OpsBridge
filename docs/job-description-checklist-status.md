## Main gaps to prioritize

1. Run the existing RAG evaluation harness in hosted CI and record its results; this remains configured but not yet verified.
2. Complete runtime verification of cross-service traces and provider attempt events, then add end-to-end failure attribution, alert notifications, and incident runbooks.
3. Finish automated product verification: get a successful hosted run of the Docker-backed Playwright workflow and projection assertion. The workflow is configured for RabbitMQ, a separate worker, PostgreSQL, the AI runtime's safe mock-provider mode, Kafka outbox publication, and a privacy-checked PostgreSQL projection. A low-volume SQLite load baseline now exists for Locust, k6, and JMeter; repeat load runs against PostgreSQL before making capacity claims. The worker intake page also has an automated axe WCAG 2.1 A/AA scan; manual accessibility checks remain.
4. Review a credentialed AWS plan and deploy one coherent workflow with health, log, scaling, and rollback evidence. The Terraform slice now includes the worker, realtime service, and Kafka projection consumer; external brokers and full observability still need deployment/runtime verification. Avoid provisioning every listed cloud service just to check names off.
5. Add one advanced distributed-systems exercise (for example, Kafka replay/schema compatibility or a failure-recovery scenario) and document its limits.
6. Keep job-specific study outside the product for DSA, CS fundamentals, interview practice, and professional skills.

## Count interpretation

The original checklist has hundreds of individual skill bullets, many describing concepts rather than a tool or an independently verifiable artifact. A single exact “added / missing” count would overstate coverage: a source file can demonstrate a starter example without demonstrating production competence. The technology-index counts and evidence-based status for each area are in [the detailed inventory](job-description-skill-gap.md). Use the table above as the quick list: a group marked “covered” still may have important partial items listed beside it.
