## Named technology index

- **Present in code/config examples:** JavaScript, TypeScript, Python, Java, Go, SQL; React, Next.js, Angular, Vue, React Native/Expo, Flutter; Tailwind, MUI, Bootstrap; Express and Hono; FastAPI, Django, Celery; Spring Boot/MVC/Cloud, Hibernate/JPA, Maven, Gradle, JUnit; PostgreSQL, MySQL, Oracle, MongoDB, DynamoDB, Redis, Elasticsearch, Neo4j, Memgraph; LangChain, LangGraph, AutoGen, Semantic Kernel; AWS service examples; Docker, Kubernetes, Terraform, CDK; GitHub Actions, Jenkins, GitLab CI, Bitbucket Pipelines; Kafka, RabbitMQ, NATS, SQS/SNS; Playwright, Postman, k6, Locust, JMeter; OpenTelemetry; the named provider integration examples.
- **Partial or docs-only:** GCP is narrow (Cloud Run/Artifact Registry plus an opt-in GKE Autopilot/Secret Manager Terraform lab); Azure has a narrow Container Apps example; Flutter iOS/device OIDC execution, several external service adapters, CI provider runs outside GitHub, and many cloud services remain unverified.
- **Not claimed as implemented:** NestJS (excluded), Angular/Vue/React Native/Flutter production deployment, Oracle/MongoDB/DynamoDB/graph adapter operations at production depth, and regulated healthcare/financial compliance operations.

## Recommended next work from this comparison

1. Get the expanded Docker-backed workflow through a successful hosted run, including PostgreSQL, RabbitMQ, a separate worker, Kafka consumer projection and the privacy-checked event report; retain the cross-browser and API contract checks.
2. Run the configured RAG evaluation and security workflows in hosted CI, capture the results, and compare the optional cross-encoder on/off only if retrieval evaluation can measure its quality and latency impact.
3. Pick one low-cost cloud target and deploy the core workflow with secrets, monitoring, a documented rollback, and a successful end-to-end check. Avoid deploying every cloud example.
4. Run the hosted observability job to verify alert delivery; then close operational gaps in trace continuity, production notification, incident/rollback runbooks, and one recovery exercise.
5. Keep interview and professional-skill practice in a separate evidence log; adding more frameworks to the product will not demonstrate those skills.
